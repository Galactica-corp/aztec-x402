# x402 на Aztec — отчёт

## Исходный план

Задача — сделать оплату API-запросов приватными токенами на Aztec через протокол x402 (HTTP 402).

Суть: клиент запрашивает платный ресурс, сервер отвечает "заплати", клиент переводит токены приватно (ни отправитель, ни получатель не раскрываются), сервер проверяет оплату и отдаёт данные.

По плану нужно было сделать 4 компонента:
1. **Плагин механизма** — логика оплаты и проверки для клиента и сервера
2. **Middleware для сервера** — оборачивает эндпоинты, возвращает 402 если не оплачено
3. **SDK для клиента** — обёртка над fetch, автоматически обрабатывает 402 и платит
4. **Демо** — простой API за платной стеной, показывающий весь флоу от начала до конца

Архитектурные решения из плана:
- Только приватные переводы (оба баланса скрыты)
- Проверка оплаты через PXE (локальный узел Aztec) — сервер обнаруживает входящие токены
- KYC обрабатывается контрактом (отложено)
- Газ платит клиент

## Что сделали

Все 4 компонента реализованы и работают:

- **5 пакетов** в монорепо: core, mechanism, client, middleware, demo
- **Полный HTTP 402 флоу**: клиент получает 402 → платит → повторяет запрос → получает 200 с данными
- **Приватные переводы** на Aztec sandbox v0.87.9 — балансы скрыты, оплата проходит
- **Демо**: сервер отдаёт "погоду" за 0.10 oUSD, клиент платит и получает ответ

Попутно исправили 3 бага совместимости с Aztec SDK v0.87.9:
- `mint_to_private` поменял сигнатуру — добавился параметр `from`
- `.simulate()` теперь возвращает значение напрямую, а не в обёртке `{ result }`
- Все адреса нужно передавать как объекты `AztecAddress`, а не строки

## Главная проблема и как решили

В плане было отмечено: **"PXE note discovery — самый рискованный неизвестный"**. Так и оказалось.

**Проблема**: Алиса переводит токены Бобу. Перевод проходит (баланс Алисы уменьшается). Но когда сервер (Боб) проверяет свой баланс — видит 0. Сервер не может подтвердить оплату.

**Почему**: Изначальная логика проверки — замерить баланс до и после обнаружения заметок (notes), и проверить разницу. Но в sandbox Алиса и Боб используют общий PXE, где заметки обнаруживаются мгновенно. Оба замера возвращают одинаковое значение → разница = 0 → "оплата не прошла".

**Решение**: Заменили проверку дельты на проверку порога — убеждаемся, что баланс Боба не меньше требуемой суммы. После этого демо заработало полностью.

## Текущие ограничения

1. **Проверка оплаты упрощена** — сейчас проверяем только "баланс >= сумма", а не "именно этот перевод был за этот запрос". Для продакшена нужно отслеживать конкретные платежи через nonce заметок или журнал.

2. **Кошелёк** — используем предустановленные тестовые аккаунты из sandbox. По плану нужен встроенный JS-кошелёк с деплоем контракта аккаунта на сеть. Интерфейсы абстрагированы, подмена будет простой.

3. **Токен** — используем стандартный TokenContract из Aztec SDK, а не AIP-20 от defi-wonderland. API совпадает, замена на настоящий стейблкоин потребует минимальных изменений.

4. **KYC/compliance** — не реализовано, ждём контракт от Fred с хуком `check_certificate()`.

5. **Только sandbox** — devnet деплой не сделан.

6. **Защита от повторного использования платежа (replay)** — отсутствует. Один и тот же платёж теоретически можно предъявить повторно.
