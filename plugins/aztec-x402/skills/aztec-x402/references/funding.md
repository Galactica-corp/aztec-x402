# Funding the agent from Ethereum

`aztec-x402 fund` lets the user move funds from their own Ethereum wallet to your Aztec account. The user opens a funding page, connects a browser wallet (MetaMask or any EIP-1193 wallet), and signs the transactions the CLI planned. You find the deposit on L1 and claim it on Aztec.

The claim secret is generated by the CLI and stays in your agent home (`deposits.json`, mode 0600). The page and the L1 transaction only carry its hash, so nobody who sees the page or the link can claim the deposit.

## Pick the mode

Browser wallets load only on `https://` and `localhost` pages, so the page must reach the user's browser on one of those.

- **Local** — `aztec-x402 fund`. You serve the page at `http://127.0.0.1:<port>/?t=<token>`. Use it when the user's browser runs on the same computer as you — the usual case for a local coding agent.
- **Hosted** — `aztec-x402 fund --hosted`. A link to the hosted copy of this skill's page (`assets/fund.html`, served at `https://aztec-x402.unfz.to/fund.html`), with the deposit plan in the `#fragment` — which browsers never send to the host. Use it when you run on a server, in a container, or in the cloud, or when a local link does not open for the user.

In both modes you watch L1 for the deposit; the page never has to reach you.

## Steps

1. **Explain first.** Tell the user what they will sign and what you will receive — the route table below — before they act. Check the route matches their goal: the testnet route funds your gas, not your USDC. They need a little L1 ETH for gas (0.01 Sepolia ETH is plenty; any public Sepolia faucet). The L1 deposit token comes from a public faucet transaction the page includes when needed. The Aztec-side claim costs them nothing.
2. **Start it.**
   - When you can keep a background process: `aztec-x402 fund [--hosted] [--amount N]`. It blocks until the deposit is claimed or 60 minutes pass. In Claude Code run it with Bash `run_in_background: true` and read its output file; elsewhere, `aztec-x402 fund > fund.log 2>&1 &` and read `fund.log`.
   - When you cannot: `aztec-x402 fund --hosted --no-wait` prints the link in its JSON (`url`) and exits. After the user says they deposited, run `aztec-x402 fund claim`.
3. **Hand over the URL.** It appears as `Funding page: …` within a few seconds. Give the user the full URL — the local `?t=` token and the hosted `#…` fragment are both required. Tell them to check that the agent address on the page matches yours.
4. **Wait for the result.** After the deposit is mined, the L1→L2 message needs a few minutes to reach Aztec, then you prove the claim. Done when `fund` (or `fund claim`) prints `"ok": true` with a `claimTxHash`. Confirm with `aztec-x402 balance` — Fee Juice shows under `feeJuice` — and report it to the user.

While `fund` or `fund claim` runs it holds the wallet database: run no other wallet commands until it finishes. If the user abandons the flow before sending the deposit, stop the background process; nothing moved and nothing needs cleaning up.

## Routes by network

| Network | Route | User signs on L1 | Agent receives |
| --- | --- | --- | --- |
| testnet (Aztec 5.x, Sepolia) | Fee Juice portal | faucet mint of test FEE (if needed), approve, `depositToAztecPublic` | Fee Juice (Aztec gas) in your account, shown by `balance` under `feeJuice`. On testnet you still pay fees through the free sponsored fee payer, so this route mainly demonstrates the deposit flow. |

Fee Juice deposits are public on L1 by protocol design: the amount and your Aztec address are visible on Sepolia. Payments you make afterwards stay private.

A stablecoin route (USDC: Ethereum → private USDC on Aztec, one Permit2 signature) becomes available with the Aztec 6 testnet. Until then, test USDC comes from `aztec-x402 faucet`.

## Recovering

- The page closed, the command stopped, or you used `--no-wait`: `aztec-x402 fund claim` searches L1 for every pending deposit, then waits for the message and claims; same 10-minute timeout as `pay`. `unsigned` in its output counts deposits not found on L1 yet.
- The wallet showed "nonce too low": the page retries and asks the user to sign again.
- `message_timeout`: the L1→L2 message was not ready after 30 minutes. Run `aztec-x402 fund claim` later; the deposit is not lost.
- The deposit reverted on L1 or the user rejected a signature: nothing moved. Start `aztec-x402 fund` again.
