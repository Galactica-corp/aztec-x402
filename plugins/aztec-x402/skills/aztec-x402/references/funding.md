# Funding the agent from Ethereum

`aztec-x402 fund` lets the user move funds from their own Ethereum wallet to your Aztec account. You serve a local web page. The user connects a browser wallet (MetaMask or any EIP-1193 wallet), signs the transactions the CLI prepared, and the CLI claims the deposit on Aztec.

The claim secret is generated by the CLI and stays in your agent home (`deposits.json`, mode 0600). The page only sees its hash inside the deposit calldata, so whoever sees the page cannot claim the deposit.

## Steps

1. **Explain first.** Tell the user what they will sign and what you will receive — the route table below — before they act. Check the route matches their goal: the testnet route funds your gas, not your USDC. They need a little L1 ETH for gas (0.01 Sepolia ETH is plenty; any public Sepolia faucet). The L1 deposit token comes from a public faucet transaction the page includes when needed. The Aztec-side claim costs them nothing.
2. **Start the page in the background**: `aztec-x402 fund [--amount N]`. The command blocks until the deposit is claimed or 60 minutes pass, then the page stops working. In Claude Code run it with Bash `run_in_background: true` and read its output file; elsewhere, `aztec-x402 fund > fund.log 2>&1 &` and read `fund.log`.
3. **Hand over the URL.** The output shows `Funding page: http://127.0.0.1:<port>/?t=<token>` within a few seconds. Give the user the full URL — the `t` token is required. The CLI also tries to open a browser on the machine it runs on.
4. **Wait for the result.** The page walks the user through each transaction; then the L1→L2 message needs a few minutes to reach Aztec, and the CLI proves the claim. Done when the background command prints `"ok": true` with `claimTxHash` and `l2Balance`. Report those to the user.

While `fund` is running it holds the wallet database: run no other wallet commands until it finishes. If the user abandons the flow before sending the deposit, stop the background process; nothing moved and nothing needs cleaning up.

## When the agent runs on another machine

The page binds to `127.0.0.1`, so it works when the user's browser runs on the same computer as you — the usual case for a local coding agent. When you run on a server, in a container, or in the cloud, or the user says the link does not open, start it with `aztec-x402 fund --host 0.0.0.0 --port 8402 --no-open` and have the user forward the port (`ssh -L 8402:localhost:8402 <agent-host>`), then open the URL with `localhost:8402`.

## Routes by network

| Network | Route | User signs on L1 | Agent receives |
| --- | --- | --- | --- |
| testnet (Aztec 5.x, Sepolia) | Fee Juice portal | faucet mint of test FEE (if needed), approve, `depositToAztecPublic` | Fee Juice (Aztec gas) in your account. On testnet you still pay fees through the free sponsored fee payer, so this route mainly demonstrates the deposit flow. |

Fee Juice deposits are public on L1 by protocol design: the amount and your Aztec address are visible on Sepolia. Payments you make afterwards stay private.

A stablecoin route (USDC: Ethereum → private USDC on Aztec, one Permit2 signature) becomes available with the Aztec 6 testnet. Until then, test USDC comes from `aztec-x402 faucet`.

## Recovering

- Page closed or the command stopped after the user sent the deposit: `aztec-x402 fund claim` finishes every deposit that has an L1 transaction. It waits for the message and claims; same 10-minute timeout as `pay`.
- `message_timeout`: the L1→L2 message was not ready after 30 minutes. Run `aztec-x402 fund claim` later; the deposit is not lost.
- The deposit reverted on L1 or the user rejected a signature: nothing moved. Start `aztec-x402 fund` again.
